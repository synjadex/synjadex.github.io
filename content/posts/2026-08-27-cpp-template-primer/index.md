**模板(template )**——C++的最大特色之一，C++**泛型编程**和**元编程**的基石，STL（标准模板库）的核心就是建立在模板上的。

通俗地说，它让你在写代码时，先把“数据类型”当作一个**占位符**（参数），而不是写死具体的类型。等编译时，编译器会根据你传入的实际类型，自动生成对应的具体代码。

你可以把它想象成**“代码的模具”**——模具本身不是最终产品，但往里面注入不同的“材料”（类型），就能压铸出不同的“零件”（具体函数或类）。



泛型编程就是写出可以适用于**不限定数据类型**的代码，比如STL里的各种通用容器`std::vector`、`std::array`等等。模板这个名字就很形象了，就是一种模具代码，根据传入的类型生成对应的代码，这就把功能实现和数据类型给分开了（解耦），当然这样做的代价是更长的编译时间，因为编译器要根据模板和类型生成多份代码。

元编程就是**写控制代码的代码**，包括代码生成，代码检查，代码修改等等。



### 模板种类概况

到C++26为止，模板可以分成5种核心类型，它们按引入标准的时间顺序分别是：

| 模板类型     | 引入标准 | 核心作用                     |
| :----------- | :------- | :--------------------------- |
| **函数模板** | C++98    | 定义通用**函数**             |
| **类模板**   | C++98    | 定义通用**类**               |
| **别名模板** | C++11    | 为一族**类型**创建别名       |
| **变量模板** | C++14    | 定义一族**变量**             |
| **概念**     | C++20    | 对模板参数施加**编译期约束** |



### 函数模板与类模板 (C++98)

这是最基础、最核心的两种模板，从C++诞生之初就存在。

- **函数模板**：定义一个通用函数，参数和返回类型可被参数化。

  ```c++
  template <typename T>
  T max(T a, T b) {
      return (a > b) ? a : b;
  }
  ```

  调用时：`max<int>(1,2)` —— 编译器生成 int 版本的 `int max(int a, int b)`

  调用时：`max<double>(1.5, 2.0)` —— 编译器生成 double 版本的 `double max(double a, double b)`

  **另外，**在C++11时引入了**函数模板参数类型自动推导**，这意味着可以省略写尖括号里的类型参数，编译器会自动推导出来。比如上面直接省略写成`max(1,2)`和`max(1.5, 2)`也行。

  

- **类模板**：定义一个通用类，其成员变量和函数的类型可被参数化。`std::vector<T>` 就是最典型的例子。

  ```c++
  template <typename T>
  class Box {
      T content;
  public:
      Box(T val) : content(val) {} 
      void set(T val) { content = val; }
  };
  // 使用时：Box<int> box1;   Box<string> box2;
  // 使用 C++17 及以后，可以这样写：
  Box box1(10);      // 自动推导为 Box<int>
  Box box2("hello"); // 自动推导为 Box<const char*>（注意这里推导为指针）
  ```
  
  注：在C++17时引入了**类模板参数推导（CTAD）**，依赖**构造函数**来推导类型，也就是说如果上面那个类里没有构造函数，那么是不可以类型推导的，必须指明类型。而且有时候类型推导得到的类型并不是我们预期的类型，所以建议写明类型，就不要偷懒了。





### 别名模板与变量模板 (C++11/14)

随着模板元编程的深入，为了更方便地操作类型和值，C++11和C++14引入了新的模板形式。

- **别名模板 (Alias Template, C++11)**：为模板化的类型创建一个新的名字，简化复杂类型的书写。

  ```c++
  // 为 std::vector<std::string> 这类容器创建一个别名模板
  template <typename Allocator>
  using StringVector = std::vector<std::string, Allocator>;
  
  // 使用时
  StringVector<std::allocator<std::string>> myVector;
  ```

  

- **变量模板 (Variable Template, C++14)**：定义一个一族变量，常用于在编译期存储计算结果，是模板元编程的利器。

  ```c++
  // 定义一个变量模板，用于获取 Pi 的值
  template <typename T>
  constexpr T pi = T(3.1415926535897932385);
  
  // 使用时，会根据类型 T 生成对应的变量
  float pi_f = pi<float>;     // float 类型的 Pi
  double pi_d = pi<double>;   // double 类型的 Pi
  ```



### 概念与约束（C++）

这是C++20中引入的重大特性，用于解决传统模板错误信息冗长、难以调试的问题。

简单来说，在C++20之前，当类型参数传入模板，编译器开始生成时，不会检查生成的对不对，会产生错误的类型会一路传播下去，直到代码生成完成才会报错，而且报错通常是成败上千行的，极其晦涩混乱。而C++20引入概念和约束后，会对模板参数进行检查，符合就放行，不符合就拦截，直接抛出错误。这样就让模板报错不再冗余，代码意图也变得更清晰了。所以说概念和约束是模板的重大更新。

- **概念 (Concept)**：为模板参数定义一组**编译期**必须满足的条件（约束）。

  ```c++
  // 定义一个概念，要求类型 T 支持 < 运算符
  template <typename T>
  concept Comparable = requires(T a, T b) {
      { a < b } -> std::convertible_to<bool>;
  };
  
  // 使用 Comparable 概念约束模板参数
  template <Comparable T>
  T max(T a, T b) {
      return (a > b) ? a : b; // 现在可以安全地使用 < 了
  }
  ```

  如果传入一个不支持 `<` 运算符的类型，编译器会给出清晰得多的错误信息，而不是一长串模板实例化堆栈。
